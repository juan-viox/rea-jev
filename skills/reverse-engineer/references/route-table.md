# Route table: target kind → first REA tool

Route before you open anything. The `UserPromptSubmit` hook may inject a System 1 route note with a `target_kind` and a probability; this file is the deterministic version of the same decision. When the note and the facts on disk disagree, the facts win. Tool names and required inputs below come from `data/rea-tool-catalog.json` (rea-agents 4.0.1); the full inventory is in [tool-catalog.md](tool-catalog.md).

## Deterministic sniff rules (code, no Jev)

The plugin's `sniff.mjs` applies these before Jev is asked; apply the same rules yourself when a path is in front of you.

- **Path tokens:** `/…`, `~/…`, `./…`, quoted paths, or anything ending in `.app .asar .apk .ipa .dmg .zip .exe .dll .dylib .so .hop .msix .appx .node`.
- **Magic bytes (first 16 bytes, read-only):** `MZ` → PE; if the PE optional header's data directory 14 (CLI header) has a non-zero RVA it is a **managed** PE, otherwise **native** PE. `\x7fELF` → ELF. `CF FA ED FE` / `CE FA ED FE` / `CA FE BA BE` (and byte-reversed) → Mach-O or fat Mach-O. `PK\x03\x04` → ZIP container; refine by extension (`.apk`, `.ipa`, `.msix`, `.appx`). A 4-byte little-endian size followed by JSON starting with `{"files"` → ASAR.
- **Directories:** contains `Contents/MacOS` → macOS app bundle (native); contains `package.json`, `main.js`, or `app.asar` → JavaScript application; contains `AndroidManifest.xml` → Android.
- **Endpoints:** `http://127.0.0.1:<port>` or `http://localhost:<port>` is a loopback CDP endpoint (browser or Electron); `ws://127.0.0.1:9229/...` style is a V8 Inspector endpoint. REA accepts loopback only.

## The table

| Target kind | Recognized by | First tool (required input) | Typical follow-ups | What static evidence cannot establish |
|---|---|---|---|---|
| `native_binary` — Mach-O/ELF/PE executable or library, macOS `.app` bundle, Hopper `.hop` analysis database | Mach-O/ELF magic; `MZ` without CLI header; directory with `Contents/MacOS`; `.hop`, `.dylib`, `.so`, `.dll` (native), `.exe` (native) | `open_binary(path)`, then `binary_overview` when metadata or inventory context helps (optional `provider_id`, `snapshot_path`) | Literal first: `search_strings(pattern)`, `trace_feature(query)`, `find_xrefs_to_name(name)`, `search_procedures(pattern)`. Then `analyze_function(procedure)`, `procedure_pseudo_code(procedure)`, `xrefs(address)`, `procedure_callers`/`procedure_callees(procedure)`, `get_call_graph(address)`, `trace_call_path(start)`, `trace_native_values(procedure)`, `inspect_native_api(procedure)`. | `javascript_application` — Electron app, `.asar`, extracted or minified bundle, source maps | ASAR magic or `.asar`; directory with `package.json`/`main.js`/`app.asar`; `.js` bundle with `.map` | `analyze_javascript_application(input_path)` (optional `format`: `auto`, `asar`, `directory`). Do **not** call `open_binary` first | `trace_application_feature(seed, application)` with one literal seed (module, route, string, IPC channel, native export) and a `direction`; `trace_javascript_semantics(application, query)`; two versions analyzed once each → `compare_application_versions(left, right)`; one export's return shape → `compare_javascript_export_shapes`; port vs original → `compare_source_to_bundle(reference, application)`; with runtime Evidence → `reconcile_javascript_runtime(static_layers, runtime_observations)`. `application`/`left`/`right` accept `{"kind":"retained-evidence","evidence_id":"ev_…"}` on the same connection | Runtime reachability, IPC registration, BrowserWindow defaults, preload or contextBridge policy enforcement; dynamic or ambiguous channel names; which modules of a loaded bundle executed; a requested `.node` member is not a verified native export |
| `managed_assembly` — .NET PE/CLI `.dll` or `.exe` | `MZ` with a non-zero CLI header data directory | `inspect_managed_artifact(path)` | `inspect_managed_members(path)`, `inspect_managed_native_boundaries(path)`; `compare_managed_members(left, right)`; `verify_managed_native_boundaries(managed_boundaries, native_observations)`; `project_managed_application_graph`; decompiler output → `import_managed_reconstruction(static_members, decompiler, methods)` (recorded as analyst inference) | Anything that needs loading, reflecting, or executing the assembly; native addresses behind P/Invoke declarations; decompiled C# as canonical truth |
| `android_apk` — Android `.apk` | `PK` magic with `.apk`; directory with `AndroidManifest.xml` | **Not in rea-agents 4.0.1.** `inspect_android_package` and the rest of the Android (JADX) family ship in a later REA release. Fallback: `open_binary(path)`, then `inspect_artifact` | `extract_artifact` to materialize files; re-route each member (`lib/*.so` → `open_binary(path)` as native ELF; bundled JS → `analyze_javascript_application`); `compare_artifacts(left, right)` across two APKs | Dalvik bytecode semantics (no decompiler in 4.0.1): class, member, and method behavior stay unknown until the pin is bumped; all runtime behavior |
| `package_archive` — `.zip`, `.ipa`, `.dmg`, `.msix`, `.appx`, other containers | `PK` magic, listed extensions, or `.dmg` | `open_binary(path)`, then `inspect_artifact` (optional `integrity_policy`: `fail` default, `record-and-continue`) | `extract_artifact` (fresh REA-chosen temp dir; no destination argument); then route each extracted member by this table; `compare_artifacts(left, right)` on two inventories; DMG inventory uses a read-only mount on supported macOS hosts | Behavior from filenames, strings, or layout alone; contents of encrypted entries or symlink targets (inventory facts only); child inventory when only root identity was available |
| `website_in_browser` — a page or site the user has open, or a Chrome DevTools endpoint | URL token; loopback CDP endpoint | `list_browser_targets(cdp_endpoint)` (optional `allowed_origins`) | Passive: `inspect_web_page`, `analyze_web_bundle(cdp_endpoint, target_id)`, `observe_web_session(cdp_endpoint, target_id)`, `discover_webmcp_tools(cdp_endpoint, target_id)`, `capture_web_screenshot(cdp_endpoint, target_id)`; compare with `compare_web_captures`, `compare_web_screenshots(before, after)`. Active (runtime-class, gated): `capture_browser_scenario(browser, start_url, actions)` only when passive observation cannot exercise the behavior | Prior activity before the attach window; that REA clicked, navigated, evaluated JavaScript, or contained the page's network; credentials, cookies, authorization headers, storage values, raw bodies (deliberately absent); WebMCP tools are untrusted page-declared inventory |
| `electron_or_node_runtime` — a running Electron or Node process with an inspector endpoint | Loopback CDP endpoint serving `file://` targets; `ws://127.0.0.1:9229` style inspector endpoint | `list_electron_targets(cdp_endpoint)` or `list_javascript_runtime_targets(inspector_endpoint)` | `inspect_electron_page`; `observe_javascript_runtime(inspector_endpoint, target_id)`; combine with static graph via `reconcile_javascript_runtime(static_layers, runtime_observations)`; active run (runtime-class, gated): `capture_electron_scenario(executable_path, application_path)` | That every module in an observed bundle executed; IPC payload values; renderer behavior REA never evaluated |
| `source_repository` — ordinary source the user already has | No artifact token; repository files | None. Use normal repository tools; do not run REA readiness or provider commands | — | — |
| `unknown_or_missing` — nothing concrete named | No path, URL, or endpoint resolves | Ask the user which artifact to inspect | — | — |

**Runtime captures** (`capture_process_scenario(executable)`, `observe_native_ui(pid, window_id)`, `capture_native_ui_scenario(pid, window_id, steps)`, `capture_browser_scenario`, `capture_electron_scenario`) are the only way to establish execution, timing, traffic, or live state. They run the declared target and nothing broader, are `runtime`-class for the gate (expect an `ask`), and are not a security sandbox. Native UI observation needs an active Mach-O target and macOS Accessibility/Screen Recording permission.

## Ask when ambiguous

Ask the user before opening anything when any of these holds: the route note's `target_kind` confidence is below 0.5 or its choice is `unknown_or_missing`; two target kinds each carry more than about 0.25 probability; a human-readable app name resolves to more than one installed artifact; or no path, URL, or endpoint exists on disk or on the network. List the candidates you found and let the user pick. Never choose an example app on the user's behalf, and never bind a second native session to "see what happens". When a tool you expect is unavailable for the bound target, call `binary_session` with `{}` and read `tool_availability` for the reason and remediation instead of guessing another route.
