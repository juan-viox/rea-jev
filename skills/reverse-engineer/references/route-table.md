# Route table: target kind → first REA tool

Route before you open anything. The `UserPromptSubmit` hook may inject a System 1 route note with a `target_kind` and a probability; this file is the deterministic version of the same decision. When the note and the facts on disk disagree, the facts win. Tool names and required inputs below come from `data/rea-tool-catalog.json` (rea-agents 6.5.0); the full inventory is in [tool-catalog.md](tool-catalog.md).

## Deterministic sniff rules (code, no Jev)

The plugin's `sniff.mjs` applies these before Jev is asked; apply the same rules yourself when a path is in front of you.

- **Path tokens:** `/…`, `~/…`, `./…`, quoted paths, or anything ending in `.app .asar .apk .ipa .dmg .zip .exe .dll .dylib .so .hop .msix .appx .node`, in one of the artifact extensions rea-agents 6.5.0 reads (`.wasm .sqlite .sqlite3 .db .db3 .pcap .pcapng .har .saz .qlog .sqlog .mitm`), or in a firmware extension (`.fw .rom .hex .ihex .srec .uf2 .ubi .squashfs .trx .dfu`). `.bin` and `.img` are not path tokens on their own: they name anything.
- **Magic bytes (first 64 bytes, read-only):** `MZ` → PE; if the PE optional header's data directory 14 (CLI header) has a non-zero RVA it is a **managed** PE, otherwise **native** PE. `\x7fELF` → ELF. `CF FA ED FE` / `CE FA ED FE` / `CA FE BA BE` (and byte-reversed) → Mach-O or fat Mach-O. `PK\x03\x04` → ZIP container; refine by extension (`.apk`, `.ipa`, `.msix`, `.appx`, `.saz` → Fiddler SAZ). A 4-byte little-endian size followed by JSON starting with `{"files"` → ASAR. `\0asm` → WebAssembly module. `SQLite format 3\0` → SQLite database. `A1 B2 C3 D4` / `D4 C3 B2 A1` (and the nanosecond forms `A1 B2 3C 4D` / `4D 3C B2 A1`) → pcap; `0A 0D 0D 0A` with the byte-order magic `1A 2B 3C 4D` (or reversed) at offset 8 → pcapng. A JSON head whose first keys are `"log"` and `"version"` (or `"log"` on a `.har`) → HAR; `"qlog_version"` / `"qlog_format"` (or a JSON-SEQ record separator on a `.qlog`/`.sqlog`) → qlog. Firmware: `27 05 19 56` (U-Boot uImage), `hsqs`/`sqsh` (SquashFS), `45 3D CD 28` (CramFS), `85 19 xx E0` (JFFS2), `UBI#`, `31 18 10 06` (UBIFS), `HDR0` (Broadcom TRX), `D0 0D FE ED` (device tree / FIT), `UF2\n`, `DfuSe`, `ANDROID!` (boot image), `:` + 8 hex digits (Intel HEX), `S0` + 6 hex digits (Motorola S-record). A gzip / xz / lzma / bzip2 / zstd / lz4 stream is firmware only when a firmware extension says so; `.bin` and `.img` alone are not firmware.
- **APK central directory (`.apk` only; one bounded read, ≤ 1 MiB):** an entry named `libflutter.so` → Flutter app (`flutter_app`); otherwise a plain Android package (`android_apk`). A ZIP64 or oversized directory that does not show the name within the cap stays a plain package.
- **Directories:** contains `Contents/MacOS` → macOS app bundle (native); contains `package.json`, `main.js`, or `app.asar` → JavaScript application; contains `AndroidManifest.xml` → Android.
- **Endpoints:** a CDP endpoint REA accepts is a literal loopback HTTP origin with an explicit port and nothing else: `http://127.0.0.1:<port>` or `http://[::1]:<port>`. `localhost`, `127.0.0.2`, LAN addresses, `https://`, credentials, paths, query strings and implicit ports are rejected by REA itself. The V8 Inspector endpoint for `list_javascript_runtime_targets` / `observe_javascript_runtime` has the same shape, typically `http://127.0.0.1:9229` (not the `ws://…/<uuid>` URL Node prints). The plugin's gate is deliberately looser (it only denies endpoints that would observe another machine, so `localhost:9222` passes the gate and then fails in REA with a clear error).

**Runtime captures** (`capture_process_scenario(executable)`, `observe_native_ui(pid, window_id)`, `capture_native_ui_scenario(pid, window_id, steps)`, `capture_browser_scenario`, `capture_electron_scenario`) are the only way to establish execution, timing, traffic, or live state. They run the declared target and nothing broader, are `runtime`-class for the gate (expect an `ask`), and are not a security sandbox. Native UI observation needs an active Mach-O target and macOS Accessibility/Screen Recording permission.

**Debuggers and instrumentation (rea-agents 6.5.0)** are `runtime`-class too, and the gate checks the program they name (`path`, `program`, `executable`) against the working directory and the declared target before Jev sees the call: `start_gdb_session` then `gdb_console(session_id, command)`; `start_rizin_debug_session(path, inferior_tty)` then `rizin_debug_command(session_id, command)`; `execute_rizin_command(path, command)` for one Rizin command over a file; `cutter_command` on a running Cutter (`list_cutter_sessions` first); `start_frida_session(mode)` (`attach` to a `pid` or `spawn` a `program`), `instrument_with_frida`, `load_frida_script`, `resume_frida_session`, `unload_frida_script`; `observe_native_calls(breakpoints)` for a breakpoint trace of the bound target; `observe_web_execution(cdp_endpoint, target_id)` instruments a page. Close what you start (`close_gdb_session`, `close_rizin_debug_session`, `close_frida_session`) and read a session back with `gdb_session_status`, `rizin_debug_session_status`, `frida_session_status`, `list_frida_devices`, `list_frida_processes`. Recordings made elsewhere are read with `inspect_web_network_capture(capture_path, format)` (`har`, `mitmproxy`, `saz`, `qlog`), `inspect_pcap_capture(path)`, `inspect_packet_capture(path, fields)`, `inspect_packet_fields`, `inspect_recorded_crash(path)`, `decode_signal_recording(path, decoders)`; their results describe observed behavior and the evidence hook treats them as runtime evidence, not static analysis.

### `capture_browser_scenario` behind an outbound proxy

In launch mode (`browser: {"mode": "launch", "executable_path": …}`), rea-agents 4.0.1 started Chromium with an allow-list of environment variables (observed on 4.0.1; not re-verified on 6.5.0, so try launch mode once before falling back) (`HOME`, `PATH`, `LANG`, `TMPDIR`, the display variables and a few more) that leaves out `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY`. On a host whose traffic must go through a proxy (a cloud sandbox, a corporate network) the launched browser cannot reach the site, and the call fails with a bare `execution_failure` ("Analysis could not complete"); retrying does not help. Use connect mode against a browser you start yourself, which keeps the fresh-profile guarantee:

1. Start Chromium from a shell that has the proxy variables, with a new empty profile, on `about:blank`, with a loopback debugging port. Add `--no-sandbox` only when the host runs as root.

   ```bash
   chrome --headless=new --remote-debugging-port=9223 --remote-debugging-address=127.0.0.1 \
     --user-data-dir="$(mktemp -d)" about:blank
   ```

2. Read the `about:blank` page's `id` from `http://127.0.0.1:9223/json/list`. `list_browser_targets` will not show it: it lists only pages with HTTP(S) URLs and counts `about:blank` under `unsupported_url`.
3. Call `capture_browser_scenario` with `browser: {"mode": "connect", "cdp_endpoint": "http://127.0.0.1:9223", "target_id": "<that id>"}` and the real `start_url`. REA navigates from `about:blank` as the scenario's first step, so the requests the page makes from the first byte are recorded.
4. Stop that browser when the capture is done.

Connect mode reports `process_ownership: "external"`. As its limitations say, REA cannot guarantee launch-time context options (viewport, locale, timezone, service-worker blocking) on a browser it did not start, so state the settings you launched with when they matter to a conclusion.

## Other targets rea-agents 6.5.0 reads

These have no `target_kind` of their own. They route as `native_binary` or `package_archive` by sniff, or by Jev's reading of the prompt, so pick the format-aware tool yourself once the artifact is in front of you. (Firmware images, packet captures and web recordings, WebAssembly modules, SQLite databases and Flutter apps have their own kinds in the table above since rea-jev 0.3.0.)

| Artifact | First tool | Follow-ups |
|---|---|---|
| Signal recording (sigrok) | `inspect_signal_decoders` | `decode_signal_recording(path, decoders)` |
| EVM contract bytecode | `inspect_evm_interface(path)` | — |
| Go or Rust binary | `inspect_go_binary(path)` / `inspect_rust_binary(path)` | then `open_binary(path)` for procedure-level work |
| PE resources, load image, layout, raw bytes | `inspect_pe_resources(path)`, `inspect_native_load_image`, `inspect_binary_layout(path)`, `inspect_with_objdump(path)` | `search_bytes(pattern)` in the bound target; `trace_dylib_resolution(roots)` for Mach-O dependency resolution |
| Crash report | `inspect_recorded_crash(path)` | runtime evidence: the crash happened, the trace is observed |
| Electron fuses | `inspect_electron_fuses(path)` | pairs with `analyze_javascript_application` |
| Minified or bundled web app source | `recover_javascript_sources(path, output_directory)` (a mutation; gated outside cwd) | `trace_web_source_location`, `trace_web_module_imports` over the recovered graph |
| JEB project | `inspect_jeb_client` to find a running JEB, `open_jeb_project(path)` | `list_jeb_units`, `decompile_jeb_item` |
| Apple, Android, HarmonyOS app graphs | `project_apple_application_graph`, `project_android_application_graph`, `project_harmony_application_graph` | `inspect_analysis_view`; `annotate_native_function` records analyst annotations (a mutation) |

## Ask when ambiguous

Ask the user before opening anything when any of these holds: the route note's `target_kind` confidence is below 0.5 or its choice is `unknown_or_missing`; two target kinds each carry more than about 0.25 probability; a human-readable app name resolves to more than one installed artifact; or no path, URL, or endpoint exists on disk or on the network. List the candidates you found and let the user pick. Never choose an example app on the user's behalf, and never bind a second native session to "see what happens". When a tool you expect is unavailable for the bound target, call `binary_session` with `{}` and read `tool_availability` for the reason and remediation instead of guessing another route.
